# Application checks — 29 September 2026

This is a fresh audit of the current working tree. MySQL initially refused connections, then became available. The configured database is behind the repository schema: missing soft-delete columns cause client and discount requests to fail. Applying the existing schema to a disposable copy resolved the observed API failures. No customer database records or original database schema were modified.

## Verified today

- Production build passes after the changes (918 modules).
- All 16 existing unit/regression tests pass.
- 670 HTTP requests completed against a migrated disposable copy, with zero server errors. Coverage includes seven roles, authentication denial, invalid/missing records, representative project/panel/division/item mutations, client edits, payments, quotation revisions, groups, discounts and Excel upload fixtures. Expected 4xx responses are included; this does not mean 670 successful business operations.
- 157 literal/template frontend API call sites match 147 registered server routes. This checks method/path compatibility, not response schemas or runtime behavior.
- 104 JavaScript/JSX files parse successfully.
- 219 native/motion button elements have a click handler, handled form submission, or disabled attribute. This is a static wiring inventory, not proof that each action succeeds.
- Login page inspected in the browser at 375px and 320px widths. At 320px, document width and scroll width both equal 320px.
- Empty login submission shows validation feedback. A dummy sign-in with the backend unavailable shows an error and re-enables Sign In.
- All 17 owner navigation pages loaded at 320px with no document/main horizontal overflow in the observed state. Mobile menu navigation, CRM opening in a new tab and the Final Report tab worked.
- Export editor loaded at 320px without page-level overflow. A missing project shows Project not found, Retry repeats the request, and Back to projects navigates correctly.
- Git diff whitespace check reports no whitespace errors.

## Changes in this audit

- Export editor displays its load error with Retry and Back to projects controls, instead of an endless loading indicator. Late responses from an obsolete request are ignored.
- Export editor uses a single-column layout below 1200px; document preview scrolling stays inside its own container.
- Dashboard and analytics grid minimums can shrink to fit narrow screens.
- API audit failure logging now reports an error code when Node provides an empty error message.
- Added --migrate-copy to the API audit so existing repository migrations can be tested only on its disposable database. Partial results are now saved even if an assertion fails.
- Added scripts/ui-wiring-audit.js and scratch/ui-wiring-audit.json for repeatable source/button inventory.

## Remaining verification

Before using the original database with this code, apply the repository schema migrations after a backup. In particular, clients and product_discounts require the updated_at/deleted_at migrations in server/db/schema.sql. Those migrations were validated on the disposable copy only.

Not exhaustively tested: every successful button state for every role, every screen/modal at every breakpoint, external attachment/OneDrive/email integrations, varied real PDF imports and concurrent updates. Static handler checks cannot establish runtime correctness. The API audit's conditional workflows and zero-server-error criterion are smoke coverage, not exhaustive business assertions.

The npm command on this machine points to a missing npm-cli.js. Checks were run directly through Node, using installed dependencies. The machine-wide npm installation was not changed.
