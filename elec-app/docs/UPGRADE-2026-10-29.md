# Upgrade the existing live database — 29 October 2026

The supplied live_schema_oct29.sql describes MySQL 8.0.46 database horizonlb. Static comparison found all 39 application tables and only one missing application column: projects.import_source. The three item markup/manpower percentage columns remain DECIMAL(5,2); no snapshot trigger definitions appear in the export. This is a schema export, not a backup of the live records.

Do not import schema.sql or the supplied structure dump into the existing database. Deploy the updated application and upgrade the existing database in place.

## Steps on the live server

1. Stop application writes (for example, `pm2 stop horizon-app`, using your actual process name).
2. Make a full backup including data and triggers:

   ```bash
   mysqldump -u YOUR_DB_USER -p --single-transaction --triggers --no-tablespaces horizonlb > horizonlb_before_oct29.sql
   ```

   Check that the command succeeds, retain the file securely, and copy it off the server. The schema-only file supplied for comparison does not replace this backup.

3. Upload the updated application code and lockfiles. Keep the production server/.env and any existing uploaded files. Confirm DB_NAME=horizonlb and the existing production database connection settings.
4. From elec-app/server, run:

   ```bash
   npm ci
   node scripts/upgrade-oct29.js --apply
   ```

   This adds import_source if absent, changes the three percentage columns to DECIMAL(15,10), fills missing saved catalog labels, and creates the two snapshot triggers if absent. Existing prices, costs, and totals are not recalculated. It verifies unchanged row counts for every existing base table. The database account needs ALTER, UPDATE, SELECT, and TRIGGER permissions; some MySQL binary logging configurations require administrator assistance for trigger creation.

   MySQL DDL commits automatically: if a step fails, keep the app stopped, fix the reported issue, and rerun. The upgrade is designed to tolerate previously completed steps. Do not assume a failed run rolled back earlier schema changes.

5. Build the frontend and restart your actual application process:

   ```bash
   cd ../client
   npm ci
   npm run build
   pm2 restart horizon-app
   ```

6. Check server logs, login, existing projects, saved prices, and the legacy import dialog. The backend also runs the same schema preparation on startup, so resolve migration errors before restarting it.
