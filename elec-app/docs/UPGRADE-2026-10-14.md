# Update the existing Horizon LB database

The supplied production schema is named horizonlb. It already contains quotation snapshots, review history, email deliveries, procurement allocations and manual receipts. For this release, the supplied schema is missing only projects.current_version.

Keep the existing database. Do not import a local development database dump or run any database/table deletion commands.

## On the VPS

1. Back up the existing database before updating:

~~~bash
mysqldump --single-transaction -u root horizonlb > "$HOME/horizonlb-before-update-$(date +%Y%m%d-%H%M%S).sql"
~~~

Check that the command succeeds and keep the backup safely.

2. Upload the new application files. Preserve the server's existing .env, uploads directory, and any other runtime file storage. Keep DB_NAME=horizonlb and the existing database credentials in .env.

3. From the uploaded application's elec-app/server directory, apply the additive migration:

~~~bash
mysql -u root horizonlb < db/migrations/20261014_project_retention_versions.sql
~~~

The migration checks for the column before adding it. Existing rows get current_version=1; records and their existing fields remain intact. Running it again does not duplicate the column or reset version numbers. If your database account requires a password, add -p and enter it at the prompt.

4. Verify the column:

~~~bash
mysql -u root horizonlb -e "SHOW COLUMNS FROM projects LIKE 'current_version';"
~~~

5. Install the release dependencies, build the client and restart the existing application process using its actual configured service/process name. Do not create a second application process.

No new database fields are required for item notes, C.R., queue filters, progress or unsaved-change warnings. They use existing fields or frontend state. The recycle bin uses the existing deleted_at field; its scheduled cleanup only targets projects that have spent a full year in the recycle bin.

These instructions were prepared from the supplied schema listing; no commands have been executed against the production VPS.
